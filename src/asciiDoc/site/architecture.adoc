= Architecture Overview

This document provides a high‑level architectural overview of the runtime instrumentation framework. +
It summarizes the purpose of each module, shows how they interact, and includes diagrams to visualize the system.

For detailed responsibilities and boundaries, each module has its own `purpose` description.

'''

= 📐 System Architecture

The system is composed of several independent but cooperating modules. +
Together, they implement a modular Java runtime instrumentation framework based on the JVM Instrumentation API.

'''

= 🧩 Module Responsibilities (Summary)

|===
|Module |Purpose 

|xref:./modules/agent/purpose.adoc[`agent`] |Activates and configures the instrumentation system (JVM agent entry point).
|xref:./modules/collection/purpose.adoc[`collection`] |Collects and aggregates measurement data.
|xref:./modules/counter/purpose.adoc[`counter`] |Implements runtime counters and injects counter logic.
|xref:./modules/interfaces/purpose.adoc[`interfaces`] |Defines shared APIs and contracts.
|xref:./modules/metrics-cost/purpose.adoc[`metrics-cost`] |Implements cost and timing measurement for JPMS modules.
|xref:./modules/metrics-cost-unnamed/purpose.adoc[`metrics-cost-unnamed`] |Cost instrumentation for unnamed/classpath modules.
|xref:./modules/example/purpose.adoc[`example`] |Demonstrates how instrumentation behaves in real code.
|xref:./modules/tests/purpose.adoc[`tests`] |Validates correctness and stability of the instrumentation system.
|===

'''

= 🔧 Class Instrumentation Sequence

[plantuml]
----
@startuml

autonumber

participant "JVM ClassLoader" as JVM
participant "agent\npremain/agentmain" as Agent
participant "Instrumentation\nTransformer Registry" as Trans
participant "metrics-cost\nBytecode Transformer" as MC
participant "counter\nData Collector" as Co
participant "Application Class" as App

JVM -> Agent: Start JVM with -javaagent or attach at runtime

Agent -> Trans: Register ClassFileTransformer(s)

note right of Agent
agent does NOT transform bytecode
only registers and configures
end note

JVM -> Trans: load / reload Classes not transformed yet (e.g. "Application Class")

note right of Trans
metrics-cost / counter
modify bytecode
end note

Trans -> MC: delegate transform(classBytes)

MC --> Trans:
return transformedClassBytes

Trans --> JVM:
return transformedClassBytes

JVM -> App: redefineClass("Application Class")

App -> Co: emit measurement events (increase counters)

Co -> Co: calculate metrics

@enduml
----
