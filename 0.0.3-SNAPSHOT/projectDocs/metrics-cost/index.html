Purpose

The metrics-cost module implements cost and timing measurement for instrumented code.
Its responsibilities include:

  • defining cost metrics (e.g., execution time, resource usage)

  • injecting measurement logic into bytecode via a transformer

  • producing measurement events consumed by the collection module

In essence:

The metrics-cost module provides the logic and bytecode transformation required to measure execution cost at runtime.

Prinzipien für ein systemunabhängiges Kostenmodell

  • Semantik statt Maschineninstruktionen Orientiere dich an der Java Language Specification: jede Operation (+, -, *, /, %, Bitshift, Vergleich) hat eine klar definierte Bedeutung. → Weise jeder Operation eine feste „Kosten‑Einheit“ zu, unabhängig davon, wie viele CPU‑Instruktionen sie auf einer bestimmten Hardware braucht.

  • Abstrakte Kostenklassen Statt „1 CPU‑Instruktion“ oder „2 Registerzugriffe“ definierst du abstrakte Kategorien:

    • Primitive Operation (Addition, Subtraktion, Vergleich) = 1 Einheit

    • Multiplikation/Division = 2 Einheiten

    • Bitoperation = 1 Einheit

    • Methodenaufruf = 3 Einheiten → Diese Werte sind frei wählbar, solange sie konsistent bleiben.

  • Konstante Zuordnung Die Kosten pro Operation sind fix und unabhängig von der JVM, der CPU oder dem Betriebssystem. Damit bleibt deine Berechnung deterministisch.

🛠 Vorgehensweise

  1. Instrumentierungsebene festlegen

    • Nur Java‑Bytecode‑Operationen zählen (z. B. ladd, lmul, lcmp).

    • Keine Unterscheidung nach JIT‑Optimierungen oder nativen Instr
